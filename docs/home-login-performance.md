# ログイン後の初回惑星表示

既存ユーザーは、自分の保存済み惑星を先に表示し、最新データを取得後に反映する。新規ユーザーや保存値を取得できない場合は、従来の最新データ取得を待つ。

## 処理と互換性

- 軽量なbootstrapから、保存値取得と従来の`/api/me`を3Dモジュールより先に開始する。認証済みの惑星データが届いた時点で共通テクスチャも先読みする。
- `GET /api/me/planet-preview`はセッション内のGitHub IDだけで保存行を読む。クエリで他人のIDを指定できず、GitHub通信・惑星保存・セッションの惑星更新は行わない。`private, no-store`を付ける。
- 保存値の取得には別のrate limitを使い、`/api/me`の既存枠を減らさない。
- `/api/me`のプロフィール確認、最新集計、実績保護、DB保存、ログイン進捗の一度だけの通知は従来の経路で完了させる。成功時のGitHub呼び出し数は増やさない。保存値用のDB読み取りが1回増える。
- 更新中はその旨を表示する。最新取得が失敗したら保存値を保ち、「保存済みのデータを表示中」と知らせる。プロフィールリンクは確認後に表示する。
- 更新待ちの間に他の惑星や履歴を選んだ場合、その選択を遅い応答で戻さない。
- 色・主言語・言語構成・大きさ・周囲の星数が同じなら、数値や称号だけを更新してGPU資源を再利用する。見た目が変わる更新ではシーンを再生成し、登場演出を繰り返さない。

サーバーの応答後に更新処理を放置する方式は使わず、更新用HTTPリクエストの処理中に保存まで完了させる。Cloud RunのCPU制限がある環境でも、切り離したバックグラウンド処理に依存しない。

## 再現計測

```sh
npm run perf:home-login
```

本番負荷試験ではない。ローカルのExpress、Cookieを発行しない模擬セッションとRepository、使い捨てChromeコンテキストで実行する。実GitHubや本番DBには接続しない。演出は実際のThree.jsとanime.jsを使う。外部CDNによる揺れを減らすため、固定版のブラウザー依存の必要なファイルだけを起動前に読み、ローカル配信する。anime.jsの取得は計測区間外で一度だけ行い、Git管理外の`artifacts/`へキャッシュする。

- 比較元の既定値: main上の`199e77a5ad5b21ae369a79699d0233b2f36eeacd`（PR #539）。今回の採取ログにある`df97b57ef828d45fc9a35aa116fecedede72919e`は、同一ツリーのsquash前コミット。比較元のHTML、bootstrap、home、i18n、シーン資源、CSSをGitから読み、計測マークだけを追加して配信する。
- 最新取得の固定待ち: 4,050ms。前回の本番ログの`/api/me`約4.05秒をモデル化する。
- 保存値読込: 120msの固定待ち。実DBの所要時間を測った値ではない。
- 1280×720、Chrome 156.0.8078.48、SwiftShaderによるソフトウェアGPU。
- 各版1回のウォームアップを除外し、その後10回ずつ、実行順を交互に比較する。
- 時間の起点はcallback完了後のホームnavigation。OAuthの所要時間は含めない。
- 「最初の惑星描画」は、シーンに追加済みの惑星のscaleが0.01を超えた状態で`renderer.render`が戻った最初の時刻。画面への物理的なscanoutやLCPの測定ではない。
- 「描画準備」はシーン生成が完了した時刻。「最新値の準備」は最新データでシーン生成または再利用が完了した時刻。

## 結果

2026-10-30に測定。最終結果は`artifacts/home-login-performance/results.json`に各回の値と集計を保存する。初回描画、最新反映後、390px画面のスクリーンショットも同じディレクトリに保存する。

| 指標 | 変更前 中央値 | 変更後 中央値 | 変更前 標本p95 | 変更後 標本p95 |
| --- | ---: | ---: | ---: | ---: |
| 最初の惑星描画 | 5.631秒 | 2.465秒 | 5.875秒 | 3.620秒 |
| 最初の描画準備 | 4.744秒 | 0.825秒 | 4.819秒 | 1.142秒 |
| 最新値の準備 | 4.744秒 | 4.296秒 | 4.819秒 | 4.375秒 |
| APIリクエスト開始 | 0.503秒 | 0.165秒 | 0.574秒 | 0.262秒 |

最初の惑星描画の中央値は約56%短縮した。保存値を先に描き、最新値は約4.3秒で反映できることを確認した。新しい描画は保存値、更新完了後の数値は最新値を表す。

10標本のp95は標本中の最大値となる。本番の実ユーザーp95や、端末別の性能を示す値ではない。最新データ取得自体の4.05秒を短くした計測ではなく、初回描画の待ちから切り離す効果と、取得開始の前倒しを測っている。

## 機能確認

`HOME_PERF_SAMPLES=0`を設定すると比較計測を省略し、ブラウザーで次を確認する。結果は`artifacts/home-login-performance/checks.json`に保存する。

- 未登録ユーザーと保存値の読み取り失敗時も、最新データで表示できる。
- 最新取得の失敗時は保存値と失敗状態を維持する。
- 最新値が先に返った場合は、後から古い保存値へ戻らない。
- 最新値で主言語が変わる場合、ランキングと惑星を更新する。
- 他人の惑星を選択後、遅い最新応答が表示を戻さない。
- 390pxでも更新表示が収まり、最新反映時に同じシーンを再利用する。
