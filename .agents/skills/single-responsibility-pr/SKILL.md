# 単一責任コミット・PR

コミットまたはPRを依頼されたときに使用する。1つのPRには1つの目的だけを含め、既存の無関係な未コミット変更を絶対に混ぜない。

## 基本方針

- PRの目的を最初に1文で定義する。
- 目的に直接関係するファイルと差分だけを選ぶ。
- 既存の未コミット変更を削除・上書き・巻き戻ししない。
- 無関係な変更が同じファイルに混在している場合は、対象ハンクだけを選択的にステージする。
- 選択的なステージが安全にできない場合は、ファイル全体をコミットせず、ユーザーに確認する。
- コミット前後に `git status` で、意図しないファイルがステージされていないことを確認する。

## コミットメッセージ

コミットメッセージは日本語で、短く具体的に書く。

- 件名は命令形または変更内容を明確に表す表現にする。
- 句読点を末尾に付けない。
- 1行で目的が伝わる場合は本文を付けない。
- 本文を付ける場合は、変更の理由や検証内容など件名と重複しない情報だけを書く。

例:

```text
ランダム検索の計測機能を追加
```

## 実行手順

1. `git status --short`、現在のブランチ、リモートを確認する。
2. `git diff` と `git diff --stat` で既存変更を確認する。
3. 今回の目的に関係する差分を明示的に列挙する。
4. 無関係な差分を除外してステージする。必要なら `git add -p` またはパッチを使う。
5. ステージ済み差分を `git diff --cached` でレビューする。
6. 変更対象に最も近いテスト、静的チェック、ビルドを実行する。
7. テストが成功したことを確認してから日本語でコミットする。
8. コミット後も既存の未コミット変更が保持されていることを確認する。
9. ユーザーがPRを明示的に依頼した場合だけ、現在のブランチをリモートへプッシュする。
10. `gh` が利用可能で認証済みならPRを作成する。利用できない場合は、プッシュ済みブランチの比較URLを提示し、PRを作成したとは言わない。

## PRの内容

PRタイトルと本文も日本語にする。本文には以下を含める。

- 目的
- 変更内容
- 検証したコマンドと結果
- 未実施の検証と理由
- 影響範囲または互換性への注意

PRに含めないもの:

- 目的と無関係な機能変更
- 整形だけの変更
- 本番データの変更・削除・初期化
- 未検証の性能改善を断定する説明
- ユーザーが依頼していないブランチ削除やマージ

## 安全確認

- コミット前にステージ差分が単一責任か確認する。
- コミット後に `git show --stat --oneline HEAD` で内容を確認する。
- プッシュ後も作業ツリーの未コミット変更を確認し、それらをPRに含めたと誤って報告しない。
- PRを実際に作成できなかった場合は、コミット・プッシュ・PR作成を明確に分けて報告する。
